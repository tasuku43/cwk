# Work Context: Message send reconciliation

> Historical design: the former all-author candidate scope was superseded by `docs/work/reconcile-own-messages/` and the durable current-account contract.

## Verified behavior

- `messages send` creates a form body with `expandMessageBody`: ordered `[To:<account>]` tags, an optional `[rp aid=<reply sender> to=<room>-<message>]` tag, one ASCII space, then the exact caller body bytes.
- The optional reply sender is obtained by one exact same-room GET before the POST. The application receives a typed sender reference only after validating the returned room and message.
- `mapMessages` preserves the provider body bytes in `Message.Body`; `parseNotation` builds typed relation facts but does not retain tag positions, so semantic relation fields alone cannot prove the exact expanded-body suffix.
- `messages.list` can read the latest bounded 100-message window once. Its `Coverage.Complete` is false because the source is bounded. Provider access limitation is independent and must remain visible.
- `PreparedMessageBody` and `Client.PrepareMessageBody` already keep body-file bytes inside infrastructure and bind them to a client and authentication binding. The new matcher follows that opaque-handle boundary and consumes a single body snapshot rather than rereading a path.
- The shared worktree includes concurrent changes to policy, send inputs, profile validation, CLI help, and docs. Preserve these changes and coordinate catalog, capsule, CLI, and durable-doc edits.

## Decisions

- Compare only the full provider body against the full expanded payload generated by the same builder used by `messages send`. A literal exact match is the same case when no typed prefix inputs are present; no separate raw-versus-typed candidate class exists.
- If `--reply-to` is provided, perform one exact GET using the same binding to validate the target and obtain the sender used by the common builder. A failure remains a read fault, never a successful empty result.
- Always perform at most one `force=1` latest-window list read; never POST. Return all exact candidates, including duplicates and messages by other authors, without claiming authorship or invocation identity.
- `candidates_found` and `no_candidates_in_window` describe only visible exact matches in the current bounded read. Both retain `outcome=unknown`; absence cannot establish that the original send was not applied.
- Body-file input is validated through infrastructure before any GET, stored only in a request/client/binding-bound opaque handle, matched once, then discarded and zeroed. The existing typed `Request` still carries the literal `Body` or `BodyFile` path into the application, and the existing typed list result carries provider `Message.Body` values there. The reconciliation-specific preparation returns no file bytes; the matcher returns only booleans; application clears temporary source-body references after comparison. No new filesystem access is exposed to the application.
- Output contains only declared candidate refs, sender refs/names, times, bounds, access limitation, and fixed uncertainty text. It never echoes the body, path, credentials, or private causes.

## Unknowns and limits

- A changed body-file can differ from the source used during the original send; the reconciliation task sees only the current file snapshot.
- A reply target may be deleted or become inaccessible after the original send; without its current exact author the same typed prefix cannot be reconstructed, so reconciliation returns the read fault.
- Duplicate sends, an identical earlier message, an identical message by another author, delayed propagation, edits/deletions, a bounded window boundary, and access limitations prevent proving send identity or absence.

## Security notes

- The matcher is read-only and has a single call budget: optional exact target GET plus one latest-window list GET, no writes or automatic retries.
- Submitted body bytes and file path stay outside public results, errors, and logs; current typed application inputs/results retain their existing values only for the duration of the task. External author names are escaped in the CLI projection.
